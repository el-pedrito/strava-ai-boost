# Validation Criteria

> See also: [Test Specifications](test-specifications.md) | [Component Order](component-order.md)

## Infrastructure Validation

| Criterion | How to Validate | Pass Condition |
|---|---|---|
| CDK synthesis | `cdk synth` | All 7 stacks synthesize without errors |
| CDK diff | `cdk diff` | No unexpected resource changes |
| Stack deployment | `cdk deploy --all` | All stacks deploy successfully |
| DynamoDB tables | AWS Console or `aws dynamodb list-tables` | 3 tables exist with correct schemas |
| SQS queues | `aws sqs list-queues` | Processing queue + DLQ exist |
| Secrets Manager | `aws secretsmanager list-secrets` | 4 secrets exist |
| Lambda functions | `aws lambda list-functions` | 12 functions with correct configurations |
| Step Functions | `aws stepfunctions list-state-machines` | 1 state machine exists |
| API Gateway | `aws apigateway get-rest-apis` | 2 REST APIs exist |

## Functional Validation

| Criterion | How to Validate | Pass Condition |
|---|---|---|
| Webhook verification | `curl -X GET` webhook URL with hub.challenge | Returns 200 with challenge |
| Webhook notification | POST test event to webhook URL | Returns 200, message appears in SQS |
| Activity processing | Trigger with test activity | Step Functions execution completes successfully |
| Strava API integration | GET `/test/strava-connection` | Returns connected status |
| OAuth flow | Complete OAuth flow in frontend | Tokens stored in Secrets Manager |
| Dashboard data | GET `/dashboard/stats` | Returns valid statistics JSON |
| Preferences | POST `/preferences` then GET | Preferences persisted and returned |
| Module toggle | PUT `/config/modules/enduraw` | Module enabled in DynamoDB |
| Enhancement control | POST `/config/enhancement` | Enhancement status toggled |

## End-to-End Validation

| Criterion | How to Validate | Pass Condition |
|---|---|---|
| Full pipeline | Upload real Strava activity → verify enhanced description | Activity title and description updated with AI content, `@Generated by Strava AI Boost` signature present |
| Feedback loop | Modify AI description on Strava → wait for nightly analyzer | `description_modified=True` and `similarity_score` populated in DynamoDB |
| Campus Coach | Enable Campus Coach module → wait for daily extraction | Sessions appear in `coaching_sessions` DynamoDB table |
| Frontend navigation | Browse all 4 pages | Dashboard, Configuration, Preferences, Quality all render correctly |
| Error recovery | Simulate Lambda failure → check DLQ | Failed message appears in DLQ, CloudWatch alarm fires |

## Data Integrity Validation

| Criterion | How to Validate | Pass Condition |
|---|---|---|
| Activity data | Query `activities` table after processing | `activity_data_json`, `enhanced_title`, `enhanced_description` all populated |
| User config | Query `user_config` table | `modules_config`, `user_preferences` properly structured |
| Token refresh | Wait for token expiry → trigger activity fetch | Token refreshed automatically, new tokens stored in Secrets Manager |
| TTL expiry | Check `expires_at` attribute | Set to ~365 days from creation |
