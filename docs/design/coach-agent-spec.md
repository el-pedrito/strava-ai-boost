## 1. Overview

### 1.1 Purpose

The Coach Agent provides personalized, evidence-based training feedback after each activity. It is a **separate agent** from the content generation agent — different persona, different memory, different purpose.

- **Content Agent**: storyteller, fun, creative, writes Strava descriptions
- **Coach Agent**: bienveillant, factuel, orienté progrès, direct mais encourageant

### 1.2 Persona

The coach is:
- **Bienveillant** — never judgmental, always constructive
- **Factuel** — cites actual numbers, never invents data
- **Orienté progrès** — focuses on trajectory, not single data points
- **Direct mais encourageant** — says what matters without fluff, celebrates consistency

The coach is NOT:
- A cheerleader (no empty praise)
- A drill sergeant (no guilt-tripping)
- A plan generator (Campus Coach does that)
- A real-time in-run assistant (out of scope)

### 1.3 Trigger Model

One-way feedback after each activity. No conversation for now.

```
Activity completed → Content Generator runs → Coach Agent runs → Feedback stored
```

## 3. Outputs

### 3.1 Strava Description (Short Coach Block)

Placed in the Strava activity description:
- **Position**: AFTER the narrative content, BEFORE the fun fact
- **Separator**: Visual header `📊 Coach`
- **Length**: 2-3 lines max (150-250 chars)
- **Content**: One key insight + one actionable recommendation

**Format:**
```
[narrative content from content_agent]

📊 Coach
[Key insight about this session]. [Actionable recommendation for next session].

[fun fact]

@Generated by Strava AI Boost
```

**Examples:**

```
📊 Coach
Ta charge monte bien cette semaine (CTL +2). Bonne discipline sur les allures EF. Pour ta prochaine séance, un tempo 20min serait idéal pour consolider.
```

```
📊 Coach
Dérive cardiaque de 8% sur la 2e moitié — signe de fatigue résiduelle (Form à -18). Pas d'inquiétude, mais privilégie une sortie courte demain.
```

```
📊 Coach
3e semaine consécutive au-dessus de 45km — bravo pour la régularité. Attention au ramp rate (5.2), une semaine allégée la semaine prochaine serait judicieuse.
```

### 3.2 Frontend Coach Page (Detailed)

New `Coach` tab in the frontend navigation (alongside Dashboard, Preferences, Quality).

#### Sections:

**A. Weekly Summary**
- Total volume (km, hours, D+, sessions)
- Planned vs realized (Campus Coach adherence)
- Key highlight of the week
- One thing to improve next week

**B. Progression Analysis**
- Pace at same HR: 4 weeks ago vs now
- Long run distance progression
- Interval quality trend (consistency of splits)
- Efficiency metrics (cadence, ground contact if available)

**C. Load Management**
- CTL trend chart (4-8 weeks)
- Form trend chart
- Ramp rate with safe zone indicator
- Overtraining risk assessment (green/yellow/red)

**D. Recommendations**
- Next session suggestion (type + key parameters)
- Weekly focus area
- Long-term progression note (aligned with athlete objectives)

#### Data Source:

The frontend reads `coach_feedback` from the activities table via the existing `dashboard_api.py`. A new endpoint or field in the existing response returns the latest coach analysis.

## 5. Athlete Profile (New Feature)

### 5.1 Data Model

New field in `strava-ai-boost-user-configuration` DynamoDB table:

| Field | Type | Max Length | Description |
|-------|------|-----------|-------------|
| `athlete_profile` | String | 2000 chars | Free-text athlete description |

### 5.2 Content Guidelines

The athlete writes (in their language) about:
- **Objectives**: current goals, target races, time goals
- **History**: how long they've been running, key achievements
- **Experience level**: beginner/intermediate/advanced
- **Injuries**: current or recurring issues, limitations
- **What to improve**: specific areas of focus
- **Constraints**: schedule, family, work limitations

### 5.3 Example

```
Coureur depuis 2023, premier marathon avril 2026 (3h51). Objectif: sub 3h45 au prochain.
Points faibles: endurance longue, tendance à partir trop vite.
Pas de blessure actuelle. Je veux progresser sur le seuil et la gestion d'allure en course.
Entraînement 4-5x/semaine, sorties le matin avant le travail (6h-7h30).
```

### 5.4 Frontend Integration

- **Location**: Preferences page, new section "Profil Athlète"
- **Component**: Cloudscape `Textarea` with character counter (max 2000)
- **Label**: "Décris ton profil d'athlète (objectifs, historique, blessures, ce que tu veux améliorer)"
- **Persistence**: Saved via existing `user_preferences_api.py` PUT endpoint

### 5.5 Injection in Prompts

The `athlete_profile` text is injected into BOTH agents:

**Content Agent** — adds context for narrative tone:
```
## Athlete Profile
{athlete_profile}
→ Use this to adapt narrative tone and references to their goals.
```

**Coach Agent** — core context for personalized coaching:
```
## Athlete Profile
{athlete_profile}
→ Base ALL recommendations on these objectives, constraints, and history.
→ Flag if current training contradicts stated goals.
→ Reference their specific targets when giving feedback.
```

### 5.6 API Changes

**PUT /preferences** — add `athlete_profile` field to accepted body:
```json
{
  "content_preferences": { ... },
  "athlete_profile": "Coureur depuis 2023..."
}
```

**GET /preferences** — return `athlete_profile` in response.

## 6. Coach Prompt Design

### 6.1 System Prompt Structure

```python
COACH_SYSTEM_PROMPT = """# Coach Agent — Strava AI Boost

## Persona
Tu es un coach d'endurance bienveillant et factuel. Tu analyses chaque séance
dans le contexte de la progression globale de l'athlète. Tu es direct mais
encourageant — tu dis ce qui compte sans tourner autour du pot, et tu célèbres
la régularité autant que la performance.

## Philosophie
- Evidence-based: chaque observation s'appuie sur des données concrètes
- Progression > performance: la trajectoire compte plus qu'un chiffre isolé
- Régularité > intensité: la constance est la clé de la progression
- Écoute du corps: fatigue et récupération sont des données, pas des faiblesses

## Framework d'Analyse: WHAT → WHY → WHAT NEXT

Pour chaque activité, structure ton analyse ainsi:
1. **WHAT**: Que s'est-il passé? (métriques clés, comparaison au plan)
2. **WHY**: Pourquoi c'est significatif? (dans le contexte de la charge, de la forme, des objectifs)
3. **WHAT NEXT**: Quelle est la recommandation? (prochaine séance, ajustement, vigilance)

## Métriques Clés (Running)

### Zones d'allure
- Endurance fondamentale (EF): conversation possible, <75% FCmax
- Tempo/Seuil: inconfortable mais tenable 20-40min, 80-88% FCmax
- Intervalles: effort max répété, >90% FCmax
- Récupération: très facile, <70% FCmax

### Indicateurs de progression
- Pace à même FC (efficacité aérobie)
- Dérive cardiaque (decoupling): <3% excellent, 3-5% correct, >5% fatigue
- Régularité des splits (coefficient de variation)
- Volume hebdomadaire (km + heures)

### Gestion de charge
- CTL: fitness long terme (progression idéale: +3-5/semaine)
- Form: >5 frais, 0 à -10 normal, <-20 attention
- Ramp rate: <5 safe, >7 risque de blessure
- Règle des 10%: ne pas augmenter le volume de plus de 10%/semaine
- Semaine allégée: toutes les 3-4 semaines (-30% volume)

## Comparaison Temporelle
- Compare TOUJOURS avec: il y a 2 semaines ET il y a 4 semaines
- Cherche les tendances, pas les points isolés
- Mentionne les améliorations même petites

## Règles Anti-IA (même que content_agent)
- JAMAIS de tiret cadratin (—), utilise le tiret simple (-)
- JAMAIS de "il est important de noter que", "il convient de souligner"
- JAMAIS de clichés coaching ("écoute ton corps", "chaque pas compte")
- Sois SPÉCIFIQUE: "ta FC moyenne a baissé de 3bpm à même allure" > "tu progresses"
- Pas de condescendance: l'athlète est intelligent, parle-lui comme un pair

## Format de Sortie

Tu DOIS retourner un JSON valide:

```json
{
  "short_block": "📊 Coach\\n[2-3 lignes max, insight + recommandation]",
  "detailed": {
    "weekly_summary": "[Résumé de la semaine en cours: volume, intensité, adhérence au plan]",
    "progression": "[Comparaison avec 2 et 4 semaines: qu'est-ce qui s'améliore?]",
    "load_management": "[CTL/Form/Ramp: état actuel, risques, recommandation charge]",
    "recommendations": "[Prochaine séance suggérée + focus de la semaine]"
  },
  "metrics_snapshot": {
    "ctl": <number>,
    "atl": <number>,
    "form": <number>,
    "ramp_rate": <number>,
    "weekly_volume_km": <number>
  }
}
```

## Contraintes
- short_block: MAX 250 caractères (2-3 lignes)
- detailed sections: MAX 500 caractères chacune
- Langue: même langue que l'athlete_profile (français par défaut)
- JAMAIS inventer de données — si une métrique manque, ne la mentionne pas
- JAMAIS générer un plan d'entraînement (Campus Coach fait ça)
"""
```

## 8. Graceful Degradation (Strava-Only Mode)

The Coach Agent MUST provide useful feedback with Strava data alone (no Intervals.icu, no Enduraw, no Campus Coach). Integrations enrich but are never required.

### Strava-Only Analysis Capabilities

| Data Available (Strava) | Coach Can Analyze |
|------------------------|-------------------|
| Pace + HR per activity | Aerobic efficiency (pace at same HR over weeks) |
| Laps data | Interval consistency, negative splits, pacing strategy |
| Distance + time | Volume trend (weekly km), long run progression |
| Activity frequency | Consistency score (sessions/week) |
| HR over time in activity | Cardiac drift (long runs), recovery between intervals |
| Elevation | Vertical load, hill performance |
| Cadence | Running economy indicator |
| Activity type | Sport-specific analysis |

### Enrichment Layers (when available)

| Integration | Additional Insights |
|-------------|-------------------|
| Intervals.icu | CTL/ATL/Form (precise load management), ramp rate, HRV |
| Campus Coach | Planned vs realized (compliance), session intent |
| Enduraw | Weather-adjusted pace (true performance), wind/heat cost |

### Implementation Rule

The coach prompt must use conditional sections:
```
IF intervals_icu_data available:
  Include CTL/ATL/Form analysis, ramp rate check
ELSE:
  Estimate load from volume trend + HR patterns (less precise but still useful)

IF campus_coach_sessions available:
  Compare planned vs realized
ELSE:
  Analyze session structure from laps alone

IF enduraw_data available:
  Use adjusted pace for true performance comparison
ELSE:
  Note weather conditions if available from Strava, flag potential impact
```

## 9. Inspiration from Research

### 9.1 Patterns Borrowed

| Pattern | Source | Application |
|---------|--------|-------------|
| WHAT → WHY → WHAT NEXT framework | claude-coach | Core analysis structure |
| Readiness thresholds (HRV ↓>20% → easy day) | section-11 | Load management rules |
| Ramp rate green-light criteria | section-11 | Progression safety |
| Athlete Dossier (free-text profile) | section-11, cycling-coach | `athlete_profile` field |
| Separate memory for coaching context | cycling-coach (MEMORY.md) | `coach_mem` AgentCore Memory |
| Deterministic metrics first, LLM synthesizes | cycling-coach, section-11 | Pre-compute in `coach_data_builder.py` |
| Tolerance bands (±3bpm, ±1%) | section-11 | Avoid false positives in drift detection |
| Structured JSON output | All three projects | Consistent parsing, frontend display |

### 9.2 What We're NOT Doing (and Why)

| Feature | Why Not |
|---------|---------|
| Real-time in-run feedback | Out of scope — requires watch integration, different latency model |
| Plan generation | Campus Coach already does this — coach EVALUATES adherence, doesn't create plans |
| Conversational coaching | Phase 1 is one-way feedback. Conversation adds complexity (state management, follow-ups) — future phase |
| Workout library / templates | Campus Coach handles programming. Coach focuses on analysis and adaptation |
| Multi-sport periodization | Keep it simple — running focus first, extend later |
| Push notifications | No mobile app. Feedback lives in Strava description + frontend |

### 9.3 Key Differentiators from Research Projects

- **claude-coach** uses file-based memory (git markdown). We use AgentCore Memory (semantic search, scalable).
- **section-11** is a protocol document for any LLM. We embed the protocol in a deployed agent with structured I/O.
- **cycling-coach** has 12 tools and Telegram delivery. We have a simpler tool-less agent (data pre-built) with Strava + web delivery.

## 10. Open Questions / Future Considerations

1. **Coach feedback opt-out**: Should users be able to disable the coach block in Strava descriptions? → Probably yes, add toggle in Preferences.
2. **Feedback on coach feedback**: How does the coach learn what's useful? → Track if user edits/removes coach block (same diff mechanism as content_agent).
3. **Multi-sport**: Coach currently focuses on running. Cycling/swimming have different metrics. → Extend prompt per sport_type in Phase 2+.
4. **Rate limiting**: Coach adds ~10s to content generation (extra LLM call). Acceptable for async webhook processing. Monitor Lambda timeout.
5. **Cost**: Extra Sonnet 4.5 invocation per activity. ~$0.01-0.03/activity depending on context size. Acceptable for personal project.
